# pi-qwencloud-quota

Pi extension that surfaces QwenCloud Token Plan consumption: local token aggregation from Pi session JSONL (route D, zero credentials) plus remaining Credits from the Alibaba Cloud subscription-stats OpenAPI (route B, env-gated), plugged into gentle-pi's native usage-source hook so it renders in `/gentle:usage` and the shell bar.

## Specs

**S1** — User request, verbatim: «verifica si existe algun plugin o extension para poder ver el consumo o uso de la cuota de qwencloud». Verified answer: nothing installed; `qwen-token-plan` is absent from `SUPPORTED_USAGE_PROVIDERS` (`gentle-pi/lib/shell-usage.ts:122` = `openai-codex`, `anthropic`, `nan` only), so `/gentle:usage` reports "no subscription usage for this provider". This package is the remedy.

**S2** — User directive, verbatim: «haz B+D y evita siempre riesgos». Two routes, both mandatory; risk avoidance is a hard constraint, not a preference. Concretely:
- No session-cookie or `sec_token` scraping of `cs-data.qwencloud.com` / `home.qwencloud.com` (route C) — explicitly excluded.
- No credential may ever be hardcoded, logged, echoed, committed, or persisted to disk by this package.
- Credentials are read from environment variables only, and their absence must never throw, warn noisily, or break route D.

**S3** — User directive, verbatim: «quiza sea más conveniente npm para poder repartirlo si es necesario publicarlo». Must be a real, publishable npm package: valid `package.json` with `name`, `version`, `description`, `license`, `repository`, `files`, `main`/`exports`, `keywords`; a `.gitignore` that excludes `node_modules` and any credential-bearing file; and a README sufficient for a third party to install and configure it. Publishing itself is NOT authorized by this spec — it remains a separate human decision.

**S4** — User question, verbatim: «no puede tomar el registro que tuve hoy del login?». Resolved: no. The credential in `~/.gentle-shell/agent/auth.json` under `qwen-token-plan` is a **Token Plan API key**, which authenticates only against the inference endpoint `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1`. That endpoint returns no quota/rate-limit headers and `pi-ai/dist/providers/qwen-token-plan.js` parses none. The plan's inference key is **never** accepted by the quota endpoints (`BailianGateway.Login.NotLogined`), so Credits require an **AccessKey ID + Secret** with RAM read permission — a different credential from a different console. Reusing today's browser login would mean route C cookies, excluded by S2. Route B endpoint, pinned from the official docs (`alibabacloud.com/help/en/model-studio/get-subscription-stats`): `GET https://modelstudio.<region>.aliyuncs.com/tokenplan/subscription/stats` with `x-acs-action: GetSubscriptionStats`, `x-acs-version: 2026-02-10`, signed with the `ACS3-HMAC-SHA256` OpenAPI scheme. Response `Data.Items[]` carries `SeatCredits` / `SeatRemainingCredits` / `SeatRefreshTime` per `SeatType`; the reset time is only reported when every item's cycle end agrees. A plan with no seats (e.g. Individual) may return an empty list — that state must render as an explicit "no subscription data", never as zero remaining.

**S5** — Package location, user-selected: `G:/Proyectos/pi-qwen-usage` (independent git repo, sibling of the user's other projects; deliberately NOT inside the `landing bitnest` repo).

**S6** — Package name, user-selected: `pi-qwencloud-quota`. (Directory name differs; see L4.)

**S7** — Integration contract. Emit `gentle-pi:usage-source/v1` with payload `{schema: "gentle-pi.usage-source/v1", provider: "qwen-token-plan", pendingNote?, fetch(apiKey, fetchFn, now)}` per `gentle-pi/lib/shell-usage.ts:148-175`; gentle-shell subscribes at `extensions/gentle-shell.ts:2229-2237` and supplies the provider's real API key plus a timeout-bounded `fetchFn`. `fetch` must resolve to `ProviderUsage { provider, plan?, limits[], fetchedAt }` where `UsageLimit { name, windows[], limitReached, scope? }` and `UsageWindow { label, usedPercent, windowSeconds, resetAt, used?, budget? }`. Runnable example: `gentle-pi/docs/gentle-shell.md:239-247`.

**S8** — Route D parser semantics, pinned from measurement. Pi session records are **nested**: `{type:"message", message:{role:"assistant", model, usage:{input,output,cacheRead,cacheWrite,reasoning,totalTokens,cost}}}`. Filtering on top-level `role`/`usage` yields zero rows — this was an actual defect during investigation. Roots: `~/.gentle-shell/agent/sessions/<project-slug>/*.jsonl` (orchestrator, grouped by cwd) and `~/.gentle-shell/agent/gentle-agents/sessions/*.jsonl` (subagents). Malformed or truncated lines must be skipped, never fatal.

**S9** — Verified baseline the aggregator must be able to reproduce: 5 days (2026-11-07 → 11-11), 111 sessions, 5,898 assistant turns, 852.6M total tokens; cacheRead 825.5M = 96.8%, fresh input 17.5M = 2.0%, output 6.3M = 0.7%, reasoning 3.0M = 0.35%. Orchestrator 16 sessions / 1,889 turns / 293.9M; subagents 95 sessions / 4,009 turns / 558.8M.

**S10** — Non-goals: no npm publish, no git push, no writes outside `G:/Proyectos/pi-qwen-usage`, no modification of `~/.gentle-shell/agent/**` or gentle-pi internals, no cost estimation in USD (catalog `cost` is `0/0` for every `qwen-token-plan` model, so any USD figure would be fabricated).

**S11** — Individual-plan route (user-confirmed after the L10/L12 verification: «Sí, implementar ruta bl CLI»). The user's plan is **Individual** (L10 screenshot), and `GetSubscriptionStats` is seat-shaped — for Individual accounts the official CLI (`bailian-cli`, npm `bl`, Alibaba's own open-source tool, verified on this machine as `bl 2.9.0`) is the sanctioned way to read the plan's quota: `bl usage token-plan --output json --console-region <region> --console-site <site>` with `Authentication: Console` (browser OAuth login performed once by the user via `bl auth login --console`). Verified field shape (CodexBar issue #3020, sanitized live fixture): fractional used ratios `per5HourPercentage`, `per1WeekPercentage` with epoch-ms `per5HourResetTime`/`per1WeekResetTime`; issue #231 documents that monthly-only accounts can get an empty JSON from this command because the CLI table reads only the 5-hour/weekly fields while the underlying API also returns `per1MonthPercentage` — the documented fallback is `bl console call --api zeldaHttp.apikeyMgr./tokenplan/personal/api/v2/usage --data '{}'`, which returns every window. Rules: the CLI is spawned with a fixed argv array (never a shell), a hard timeout, and env-configurable binary/region/site; the parser deep-walks the JSON for exactly the allowlisted `per(5Hour|1Week|1Month)(Percentage|ResetTime)` keys, treats values in `0..1` as fractional used ratios and `1..100` as already-percent; a missing binary, missing login, malformed output, or unknown shape degrades into a one-line message and never throws into the session; the CLI's own auth state on disk is never read, copied, or exposed by this package.

**L8** — Unit 2, two bounded changes (S2, S8, S10 honoured; no credential stored, echoed or persisted; no console scraping).

*Defect (verified, not theoretical).* `src/usage-source.ts` emitted `aggregateSessions()` totals under `provider: "qwen-token-plan"`, i.e. the aggregate of **every** local session on disk. The gentle-shell panel therefore rendered `qwen-token-plan · local 7d · 917.0M tok` while only ~1.8M tokens had actually gone through `qwen-token-plan`; the remainder was `nan`, `openai-codex` and `claude-bridge` traffic. Any quota decision read off that line was wrong by two orders of magnitude.

*Change A — attribution.* `Aggregate` gains `byProvider`, bucketed from the `provider` field on the assistant record itself (`message.provider`, falling back to a top-level `provider`, else `unknown`); new `providerBucket(aggregate, provider)` is the only supported way to read a provider-scoped figure. Catalogues are never consulted: `deepseek-v4-flash` exists in **both** the `nan` and `qwen-token-plan` catalogues, so membership proves nothing and a model-id lookup would reintroduce the defect. Consequences: the usage-source `plan` keeps its shape `local <window> · <tokens> tok · cacheRead <share>` over the qwen subset only and appends a labelled ` · all providers <tokens> tok`; `/qwen-quota` prints `qwen-token-plan:` totals, an explicitly labelled `all providers: … · local context only, not Qwen quota` line, and a `by provider:` table (provider, turns, total tokens, cacheRead share) sorted by tokens desc; the status row became `qwen <tokens> tok · cacheRead <share>` (qwen subset), dropping the ambiguous `local` wording. `MODEL_CHANGE`/`model_change` records are still not used for attribution — only the turn's own field is.

*Change B — exhaustion detection.* New `src/exhaustion.ts`: `createExhaustionTracker(now, ttl?)` + `pi.on("after_provider_response")` (event shape `{type, status, headers}` per `pi-coding-agent/dist/core/extensions/types.d.ts:725-729`). It reads only `status`, the `Retry-After` header (case-insensitive; seconds, HTTP-date tolerated) and an `insufficient_quota` error type when the event exposes one. Records `{provider?, observedAt, resetAt}` in memory only — no disk, no request or response body, no credential. `resetAt = observedAt + Retry-After × 1000`; missing/malformed/negative header still records with `resetAt: null` (visible for `UNKNOWN_RESET_TTL_MS` = 1h); the record expires at/after `resetAt`; a non-429 response never mutates the state; a 429 attributed to another provider (`ctx.model.provider`) is ignored rather than reported as Qwen exhaustion — same misattribution class as Change A. Rendering: `exhausted · resets HH:MM` (local clock) or `exhausted · resets unknown`, appended to the status row and printed on its own line by `/qwen-quota`. Every path is wrapped: the hook never rejects into the session.

**L9** — Unit 3, two activation/rendering defects in `src/extension.ts` (S2, S7, S10 honoured: no credential read, stored or echoed; no console scraping; nothing outside this repo touched; no git mutation by the worker).

*Diagnosis (verified before editing, not assumed).* Loading the package through jiti 2.7.0 exactly as Pi does, with a mock ExtensionAPI, succeeds: the default factory runs, registers `session_start`, `after_provider_response` and `/qwen-quota`, and the handler emits the correct new-format summary. So neither the code nor the loader was broken — the running shell's behaviour was a design defect in *when* each surface was written.

*Defect 1 — the usage source was announced only on `session_start`.* A `/reload` re-activates the module without replaying `session_start` (`interactive-mode.js:5446` calls `resetExtensionUI()`, then rebinds), so the closure registered by the **previous** module instance stayed in charge and the panel kept rendering stale format and stale numbers. Fix: `registerQuotaExtension` now calls `announceUsageSource()` once in the factory body, wrapped in its own `try/catch` so a failing hook cannot block activation or the command registration. The `session_start` announce is kept (gentle-shell replaces the source for the same provider, so a second emit is a no-op in effect). The status row is also refreshed at activation **only if a `PiUi` is reachable** on the activation object (`isPiUi` probes `setStatus`/`setWidget`); Pi's `ExtensionAPI` (`types.d.ts:1209`) exposes no `ui` and the factory receives no `ctx`, so in practice this path is skipped in silence and the row still first appears on `session_start`. No ui object is invented. Observable sequence at activation (mock, no events fired): `emit gentle-pi:usage-source/v1` → [`setStatus qwen-quota` when a ui is reachable].

*Defect 2 — the table was rendered into a transient toast.* `ctx.ui.notify(message, "info")` flashes one line, so an 18-line table read as "prints nothing". The documented persistent surface is `ctx.ui.setWidget(key, content: string[], options?)` (`types.d.ts:112`). Fix: the handler now writes `renderSummary(...).split("\n")` to `setWidget(QUOTA_WIDGET_ID, lines)` and keeps a **one-line** `notify` pointer (`qwen-quota: summary in the quota widget`). Both calls are individually wrapped: a throwing `setWidget` never rejects the handler, and the toast then says `qwen-quota: could not render the quota widget` rather than pointing at a panel that is not there. `src/summary.ts` is untouched — the split happens in `extension.ts` as scoped. `PiUi.setWidget` in `src/types.ts` is now `setWidget(key: string, content: string[] | undefined, options?: unknown): void`, matching the real overload shape (`options` is `ExtensionWidgetOptions`, only ever omitted here). Clearing: `setWidget(key, undefined)`; Pi also calls `clearExtensionWidgets()` from `resetExtensionUI()`, i.e. before a `/reload` and when the session is invalidated.

*Widget cap (found while verifying, not previously documented).* Pi truncates array widgets at `MAX_WIDGET_LINES = 10` and appends `... (widget truncated)` (`interactive-mode.js` `setExtensionWidget`). The head of the summary — window, qwen plan figure, all-providers figure, per-provider and per-source rows — is what fits; per-model, per-day, per-project and the `Credits:` line fall past the cap. Reordering the summary was out of this unit's surface (`src/summary.ts` not authorized), so it is recorded here and in the README as a known limitation rather than silently accepted.

*Intentional contract change.* `notify` no longer carries the summary; it carries one line. Three existing assertions were rewritten to the new contract (they are not regressions): the exact-summary test now asserts the same lines against `setWidget` content plus a no-newline pointer toast; `session_start` now observes **two** emits (activation + start); the 429 test finds the `exhausted · resets HH:MM` line in the widget instead of the toast.
